## 💥 架构宣言：一维线性表达与高耦合全息系统的物理矛盾

离散制造供应链与 enterprise 治理，本质上是一个**强耦合、非线性、高度咬合的开放复杂巨系统（Open Complex Giant System）**。

在真实的商业与工业场景中：
* 任何一个物料缺口会引发链式坍塌；
* 任何一次到料拉快会扰动全网配额；
* 任何一次替代料置换会改变后端车间派程；
* 任何一次插单会引发全局重排产。

**人类表达与理解的物理局限**：
受限于时间轴与文本的代码一维属性，人类只能按照一维线性顺序（$1 \to 2 \to 3$）进行代码编写与文档阅读。物理真相是：**全球商业界能够直接在大脑中理解强耦合涌现系统的人不超过 3%**。

如果把整套 IPC 引擎的庞大解法直接混在一个海量数据集里一次性吞吐输出，外部测试员与系统审计专家将被复杂度瞬间淹没，完全无法理清因果做功。

## 🏛️ “单一内核 + 4 场景解耦”的软件架构物理学

为了破解“线性表达”与“高耦合系统”的矛盾，IPC 物理引擎采用了 **“单体 C++ 裸金属内核 + 4 阶段正交场景切片”** 的解耦验证架构：

```text
┌────────────────────────────────────────────────────────────────────────┐
│             IPC 统御引擎单体 C++ 内核 (main_mem3.exe)                     │
│   (包含了全部 DOD 内存网格、前缀和消纳、偏序格组替代与车间调度算子)             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 策略与数据切片驱动 (Data/Flag Slicing)
    ┌───────────────────────────────┼───────────────────────────────┐
    │                               │                               │
┌───▼───────────────────┐ ┌─────────▼─────────────┐ ┌───────────────▼───────────┐ ┌───▼───────────────────┐
│ 场景 1：L0P 前缀和消纳  │ │ 场景 2：替换料/组替代│ │ 场景 3：ITP/IOP 战略配额  │ │ 场景 4：车间 DBD 派程 │
│ 单物料 AVX-512 SIMD 并行│ │ 偏序格与动态平摊配额 │ │ 战略配额防波堤拦截     │ │ 产能锁死与 ATP 出单   │
└───────────────────────┘ └─────────────────────┘ └───────────────────────────┘ └───────────────────────┘
```

1. **底层是一套完整的大程序（`main_mem3.exe`）**：
   从最顶层的 IBP（集成业务计划），到中间层的 L0P/MRP（消纳下爆）与 DBD（组替代），再到最底层的车间派程（Scheduling），在源码层（`src/engine_main.cpp`）是一个完整的单体高性能计算内核。

2. **上层切分为 4 个清晰解耦的场景（Scenario Sandboxes）**：
   通过不同的参数与数据库输入表（`data/ipc.db`），每次测试只激活特定的物理算子通道，让读者与专家能够在 1D 线性阅读中，一步步看清全局系统的咬合做功细节。
