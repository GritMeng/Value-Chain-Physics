IPC Single-Homomorphic Engine Architecture Specification

智能计划与控制 (IPC) 模型秩序与全景计算逻辑图谱

IPC 的本质是连续时间/离散事件一维几何水位消纳模型与多层级级联约束传导秩序。本规范经过与 C++ 源码的全要素校对，将完整消纳、ECN 软硬切替、BOM多属性连通决策、跨站点运输提前期时序偏移、复合优先级打包位域、平局配额决策、高优抢单前移、联副产品降级切片排序、微观工单 TSP 换型优化、WBS CPM 调度及项目商业对账等逻辑全部融为一体。

1. 模型秩序体系与串/并行拓扑分类 (System Order & Topology)

🔗 串行拓扑算子 (Serial Operators)

Sequential

存在严格因果关系或状态依赖的计算节点。上一阶段/层级的输出是下一阶段/层级的输入，必须按拓扑序（如 LLC 码、交期顺序）严格单向推进。

  • BOM 拓扑按 LLC 码由上至下级联展开（物理站点 Material@Site 唯一编码）
  • 同 LLC 层级内替代件连通分量 (DSU) 优先级排序
  • 64-bit 复合优先级位域打包全局拉通序列
  • 三类替换料决策、供应商配额比例大者优先平局决断 (Tie-breaker)
  • 配额日历 Allotment Monday-aligned 周级回退匹配机制
  • ECN 软硬切替库存预消纳与硬截断
  • 跨站点运输提前期时序偏移 (Transshipment)
  • CTP 递归回溯与 Zero-Heap 事务 Savepoint 回滚
  • 高优订单产能抢占与前移挤占排产 (Preemption)
  • 联副产品批次降级（EXACT_FIRST / HIGHER_FIRST 降序消纳） (Co-product)
  • 微观工单 TSP 换型优化与齐套拉动 (Greedy TSP & Call-off)
  • 项目 WBS-CPM 关键路径 Forward/Backward Pass
  • 受损断料按 CSC 拓扑由下至上逆向级联传导

⚡ 并行拓扑算子 (Parallel Operators)

Concurrent

数据空间解耦、无强依赖关系的计算节点。可以利用全核算子并行推演，无锁并发消纳。

  • Hierarchy 多维属性展开与概率预测 (TFT/DeepAR)
  • 同层级物料节点的双端前缀和消纳 (SIMD Netting)
  • 多级安全库存时序段树规约合并 (Segment Tree ⊕)
  • 乐观共享库存池无锁 CAS 并发扣减
  • BOM 齐套率评估与拉动仿真分类 (GREEN/YELLOW/RED)
  • 项目对账与商业合同奖惩并行核算
  • 多 What-If 沙箱隔离评估与 3-Way Diff 比对

💡 阶段一深度逻辑与代码映射讲解：

为了防止复杂制造网状 BOM 中出现环形死锁依赖，算法通过控制 iterations 轮次，每轮将父件的 LLC 码向下传递 +1。若 iterations 超过 100 轮仍未收敛，说明 BOM 中存在循环依赖回路，引擎立即触发熔断。编译完成后，利用并查集 (DSU) 识别替代料组连通分量，按最小优先级排序后并行分发给 OpenMP 工作线程，实现无锁并行。词典以 `MaterialCode@SiteCode` 物理站点主键格式独立，实现多工厂解耦消纳。

💡 阶段四深度逻辑与代码映射讲解：

在 LBL 需求展开中，系统引入工程变更（ECN）软硬切替。对失效 `eff_end_day` 且类型为 `soft` 的物料优先消耗在手库存（分配类型 `-2`）并阻断级联需求。若父子物料在不同站点，子件到期日自动扣减该子件的跨站点运输提前期 `transshipment_lead_time`。当存在替代件组时，执行 MCDM 价值模型排序（LLC/新增采购成本/物理在手消耗成本），在一类/二类替代中，若遭遇数学平局则触发配额比例大者优先决策 (Tie-breaker)。分摊后以无锁 CAS 写入下层 `gross_demand_priority`。

💡 阶段五深度逻辑与代码映射讲解：

在 reserve_atp_and_capacity_recursive DFS 递归中，利用线程局部暂存栈 Savepoint 记录状态。若遇约束失败，直接回滚。主路线产能不足时，若订单量大，系统通过自适应拆单 (Splitting) 计算可能分配量 possible_qty 并将残量滚动至下一天；若订单量小，系统搜索同日低优先级订单并尝试将其前移一天 (d - 1) 排产，前移成功则高优订单成功抢占产能。

在晶圆分级切片中，芯片产出常伴随降级分流。`run_ipc_coproduct_dimension_planning_and_persist` 解析 EQ (精确规格) 与 GE (降级件兼容) 等规则过滤可用规格。过滤后系统支持 EXACT_FIRST（精确优先消纳，备用件从小到大升序保留高端）与 HIGHER_FIRST（大到小降序消纳防囤积）两种排序。首阶段尝试扣减 stock 物理在库，若有缺口则搜寻收率 ratio 最优的 recipe 并投料产出，副产物作为 leftover 写入 ledger 账本。

💡 阶段七深度逻辑与代码映射讲解：

在 `run_detailed_scheduling_and_calloff` 中，为平衡换型成本与延期交货，工单排序引入 TSP 贪心阻抗公式 impedance = setup_time + delay_penalty (其中 delay_penalty = delay_days * 1.5)。工单负荷跨日消纳产出 start_day，随后按其排序模拟领料并提前 1 天向仓库发起 call_request。系统评估组件齐套率率 >= 1.0 为 Fully_Kitted (绿单)，率 >= 0.4 为 Partially_Kitted (黄单)，率 < 0.4 为 Critical_Shortage (红单)。

阶段五 时序运输偏移 跨站点子件 child_due_day 顺向扣减 🔗 串行时序计算 parent.site != child.site → 扣减该子件的 transshipment_lead_time 运输期
阶段五 替代件MCDM 按 (max_llc 升序, new_cost 升序, exist_cost 升序) 对连通组排序 🔗 串行多指标排序 计算各个连通替代件的多维成本阻抗，选择阻抗最低 candidate 优先划拨
阶段五 一类替代平局 allocate_class1 差值最大化平局决断 🔗 串行平局判定 gap 相等时，选择 target_ratio 配额比例最大者优先作为替代件 (Tie-Breaker)
阶段五 二类替代平局 allocate_class2 评分最小化平局决断 🔗 串行平局判定 rating 相等时，选择 target_ratio 配额比例最大者优先作为替代件 (Tie-Breaker)
阶段五 三类替换料 actual_qty = ceil(due * per_qty * (1+scrap) / lot) * lot 🔗 串行逐轮归一化 rem_net > 0 → 扣减并剔除已决策件，重新归一化权重
阶段五 呆滞件 Swap 从同 alt_group 盈余备件调拨 (SwapRecord) 🔗 串行置换 替换缺口存在 且 current_on_hand > SS → 触发滞销置换 Swap
阶段六 CTP 递归回溯 DFS 递归树 + savepoint 栈 🔗 串行 DFS 回溯 任何约束突破（日历、产能、BOM有效期、LTB、Mix Group） → 执行 Zero-Heap 回滚
阶段六 自适应拆单 possible_qty = (avail_cap - setup - cleanup) / factor 🔗 自动切分 产能不足 且 订单量 >= 1000 → 拆单，残量滚动至下一天
阶段六 高优排程抢占 preempt_target 前移一天的 CTP 重新排产 🔗 抢单挤占 当前订单失败 且 demands < 1000 且 存在低优订单 → 尝试前移重排；成功则抢占
阶段七 晶圆降级排序 EXACT_FIRST vs HIGHER_FIRST 🔗 串行分级排序 EXACT_FIRST 优先精确规格且小到大消耗；HIGHER_FIRST 高规格优先消纳防止高端囤积
阶段七 联副产品分配 downbinning_priority 维度精确/降级判定 🔗 两阶段消纳 1. 优先使用 stock 中可用规格；2. 缺口触发最佳 recipe 批量生产注入并划拨
阶段八 TSP 换型优化 Greedy TSP 最小化 setup + delay * 1.5 🔗 串行 TSP 遍历 unvisited 寻找阻抗最小的工单作为下一工序
阶段八 工单日历消纳 工单负荷跨日消纳，动态顺延 finish_day 🔗 串行排期 工单 load > 当日产能 → 扣减完当日后 current_day++ 滚动
阶段八 齐套物料拉动 kitting_rate = fulfilled / total 判定 kit 状态 ⚡ 并行齐套评估 rate >= 1.0 → Fully; rate >= 0.4 → Partially; else → Critical
阶段九 WBS CPM 调度 Forward Pass (ES/EF) 与 Backward Pass (LS/LF) 🔗 双向拓扑 确定项目完工天数 calc_finish_day 与各 WBS 节点时延差
阶段九 项目合同对账 net_project_value = base + bonus - penalty ⚡ 并行项目对账 完工 <= bonus_offset → 获奖励；完工 > penalty_offset → 扣罚超期款
阶段十 3-Way Diff 基准 P vs 子场景 C vs 主库 M ⚡ 并行比对 P != C 且 P != M 且 C != M → 触发 409 冲突警告；否 → 下发变更
阶段十 受损级联传导 沿 CSC 拓扑自底向上逆向级联传导 🔗 串行自底向上 扣减顶层销售订单，重新平衡 ipc_financial_ledger 财务账本
