# Proposal

## Why

`ipc-core-benchmark/` 的 4 个核心计算引擎（ATP/CTP 交付承诺、ITP 主计划防波堤、IOP 执行计划刚性阻断、替代料三级决策）目前只能通过 C++ 基准测试运行：测试把数据硬编码在 `main()` 里、用 `assert` 校验，压测虽能读 CSV 却只向终端打印文本。输入数据、计算结果与决策过程对业务使用者不可见，也无法按场景、按天粒度分析。

本项目为优化引擎构建一个 Node.js 可视化演示 Demo。**计算仍由既有 C++ 引擎完成**：Node.js 按「测试场景」组织数据，把场景输入写成 CSV、调用 C++ 可执行程序、再把输入与输出的 CSV **全部**导入 DuckDB，供前端按场景、按天粒度透视分析。

## What Changes

- **为 C++ 引擎新增 CSV 输入 / CSV 输出命令行驱动**（`ipc-core-benchmark/` 内新增，**不修改**既有引擎算子与既有基准程序）：读取场景目录中的输入 CSV、调用既有算子、把结构化结果写出为 CSV。
- **测试场景（Scenario）成为数据组织的第一等概念**：每个测试场景对应一个独立目录，内含该次计算所需的**全部数据集**（`parts`、`bom`、`capacity`、`atp_supply`、`demands_master`、`demands_execution`、`substitution_group`）。既有 `data/sample/` 与 `data/` 作为两个初始场景，并支持新建场景。
- **新建 `ipc-demo/` Node.js 应用**：后端负责编排与数据管道，前端负责分析可视化。**后端不实现任何引擎算法**。
- **输入数据一并入库**：Node 把场景目录中的**输入 CSV** 以及 C++ 产出的**输出 CSV** 同时导入 DuckDB。用户可在同一界面统一查看**需求、供给、资源（产能）、计划供给**等全部信息，而非只看计算结果。
- **DuckDB 作为唯一持久与分析层**：以场景为维度组织既有数据集与每次运行的输入/输出；所有运行结果按 `run_id` 归档，支持 SQL 查询与历史对比。
- **前端可视化界面**（数据全部来自 DuckDB 查询）：
  - **场景视图**：按场景浏览输入数据集（需求、供给、产能、BOM、物料主数据、替代料组），可查看原始 CSV 内容。
  - **计划透视图（SAP IBP 风格）**：以天为时间粒度、行为关键指标、列为时间桶的计划透视表，展示供应、需求与库存的计划演进；支持按场景/物料/约束维度筛选。
  - **交付承诺视图**：BOM 层级、库存/产能水位、请求交期 vs 承诺交期时间轴、回滚标识。
  - **ITP/IOP 视图**：四维约束键（day × family × cust × region）的配额防波堤 vs 执行消耗，标出被刚性阻断的订单。
  - **替代料视图**：一类/二类/三类分组水位、配额比例、本次分配与被选中成员。
  - **性能视图**：运行耗时、处理条数、吞吐量、`run_id` 历史对比。
- **关键指标按引擎业务场景确定**（详见 specs）：供给维度含期初库存、在手、在途(SR)、计划订单、计划可用量；需求维度含独立需求、毛需求、净需求、已承诺量；资源维度含产能工时、已分配工时、剩余可用工时；平衡维度含 ATP、缺口与库存投影。
- **数据与配置**：支持场景导入与全量数据可选导入；DuckDB 路径、端口、C++ 可执行路径、场景根目录通过环境变量配置。
- **演示模式**：前端基于持久化的结果数据支持单步/动画回放。
- **文档**：`ipc-demo/README.md` 说明启动、场景组织约定、数据导入、C++ 驱动契约与 API。

## Capabilities

### New Capabilities

- `ipc-demo/scenario-management`: 以目录为单位的测试场景定义、发现、创建与数据集完整性校验，并作为输入与运行的组织维度。
- `ipc-demo/data-persistence`: 将场景的输入数据集 CSV 与每次运行的输出 CSV 导入 DuckDB，支持浏览输入数据、按 `run_id` 回溯运行结果。
- `ipc-demo/engine-service`: Node.js 编排 C++ 可执行程序完成计算——写出场景输入 CSV、调用子进程、读取输出 CSV、处置失败——并通过 HTTP API 暴露场景、输入数据与结果。
- `ipc-demo/planning-pivot`: 以天为时间粒度、行为关键指标的计划透视视图数据能力，覆盖供给、需求、资源与平衡四大指标族，支持按场景与维度筛选。
- `ipc-demo/visualization-ui`: 前端可视化界面，覆盖场景浏览、计划透视、交付承诺、ITP/IOP、替代料与性能视图，支持单步/动画回放。
- `ipc-demo/demo-runtime`: 演示应用的启动、配置、C++ 编译引导与场景引导流程，保证在本地一条命令可运行并复现文档中的基准结论。

## Impact

- **改动 C++ 侧**：在 `ipc-core-benchmark/` 内**新增** CSV 驱动的 CLI 入口与构建配置。既有引擎源码、头文件契约、既有基准程序与既有数据文件**保持一致**。
- **新增代码**：`ipc-demo/`（场景管理、后端编排服务、前端应用、DuckDB schema 与导入脚本、运行工作目录管理、测试）。
- **新增数据组织**：在 Demo 侧建立场景根目录（默认指向既有 `ipc-core-benchmark/data/`，其中 `sample/` 与根目录即为两个初始场景）；新建场景不修改既有数据文件。
- **依赖**：Node.js 运行时、`@duckdb/node-api`（或 `duckdb` Node 绑定）、Web 服务与前端构建依赖；C++ 侧沿用既有工具链（clang++/MSVC/CMake）。
- **不改动**：论文/理论层内容、`openspec/` 现有内容、既有引擎与基准程序。
- **系统边界**：Demo 面向本地演示与评审，默认绑定 `127.0.0.1`，不设计为生产多租户服务。
